# BQ 쿼리빌더 v6 — 답변 엔진 (Gemini + BQ 실행) 설계

작성 2026-07-03. 상태: 확정(사용자 승인). 이전 잠금 2개 해제 — "LLM 0"(→Gemini), "실행은 사람이 콘솔에서"(→도구가 실행).

## 0. 왜 (문제 재정의)
사용자는 SQL을 **직접 치지 않는다**. 따라서 "SQL 텍스트를 만들어 콘솔에 붙여넣게" 하는 설계는 무의미 —
노션 에이전트에 카탈로그+지침 넣은 것만 못하다(노션이 대화·후속질문 더 편함).
도구가 노션 에이전트를 이기는 **유일한 차별점 = BQ에 실제로 쿼리를 돌려 "답"을 돌려주는 것.**

→ 목표 전환: **SQL 생성기 → 답변 엔진.** 질문하면 표·차트·한줄해석이 나온다. SQL은 접힌 부산물.

## 1. 아키텍처
```
브라우저(정적 Pages)
   │  질문(자연어) + 프로퍼티(고방/U사장님)
   ▼
GAS 웹앱  (소유자 권한으로 실행, 키·자격증명 보관)
   ├─ 1) Gemini 2.5 Flash: 스키마 주입 → SQL + 한줄해석(JSON)
   ├─ 2) 출력가드 + 자가수정 1회
   ├─ 3) BigQuery dry-run: 스캔량·요금 추정
   └─ 4) BigQuery 실행(maximumBytesBilled 하드캡) → rows
   ▼
브라우저: 결과 표 + 자동 차트 + 접힌 SQL + 후속질문
```
- **키**: `GEMINI_API_KEY` → GAS Script Properties에만. repo·클라이언트 절대 미노출.
- **BQ 권한**: 웹앱 "소유자 권한 실행" → 소유자(BQ 접근 계정)로 쿼리 실행, `gobang-bigquery` 청구서 흡수. 서비스계정 불필요.
- **프록시 URL**: `src/config.ts` 상수(공개 무방, 게이트는 프록시가).

## 2. 대화형 = primary
- 입력: 자연어 질문 1개 + 프로퍼티 선택.
- 출력: **답이 주인공** — ①한줄해석 ②결과 표 ③자동 차트(dataviz 규칙) ④접힌 SQL(투명성).
- 규칙파서 해석칩/되물음 UX는 제거(대화형에서). CTR·비율 등 기존 규칙 불가 문장도 Gemini가 처리.
- **후속 질문**: 직전 질문·SQL·결과 요약을 맥락으로 유지해 "그럼 그중 모바일만" 식 이어가기.

## 3. 셀렉형
- 유지하되 종착점을 "SQL 생성"이 아니라 **"실행 → 결과"**로 승격(동일 실행·차트 파이프 재사용).
- 규칙 SQL 엔진(generate.ts)은 그대로 — 셀렉형은 결정적·무비용(LLM 안 탐), 실행만 붙음.

## 4. Gemini 프롬프트
- **지침**: 기존 스펙(2026-07-02)의 SQL 서식 규칙 — WITH base, COALESCE+SAFE_CAST, branch_type CASE 병합, `_TABLE_SUFFIX` 필수, 주석 블록. + 출력은 JSON `{sql, explanation}`.
- **스키마(grounding)**: **선택 프로퍼티 1개만** 트림 주입 — 이벤트명·파람키·타입. 고방/U사장님 동시 금지(131KB 과대). cnt 등 불요 필드 제거. dataLayer 상속 주의(이벤트 간 값 스티칭 불가) 명시.
- 모델: `gemini-2.5-flash`(용도=UX팀 내부, 저비용). 컨텍스트 캐싱으로 지침·카탈로그 재사용.

## 5. 가드 (2겹)
### 5-1 출력가드 (읽기전용·스키마)
- SQL이 `SELECT`/`WITH`로 시작(정규화 후). DML/DDL/스크립트 거부.
- `_TABLE_SUFFIX` 포함 강제(기간 없는 풀스캔 차단).
- 대상 데이터셋만 허용: `analytics_274122040`(고방)·`analytics_279311003`(U사장님).
- Gemini SQL이 카탈로그에 없는 이벤트명/파람키 참조 시 위반.
- **자가수정 1회**: 위반 내용을 Gemini에 되돌려 재생성. 2번째도 실패 → 실패 처리.
### 5-2 비용가드 (실행)
- dry-run으로 `totalBytesProcessed` → 요금 추정($6.25/TB) 화면 표시.
- `maximumBytesBilled` 하드캡(기본 10GB ≈ $0.06) → 초과 쿼리 실행 실패(요금 폭탄 원천 차단).
- 결과 행 상한(예 10k) — 초과 시 잘라 표시 + 고지.

## 6. 폴백/실패
- 프록시 네트워크 실패 or Gemini 2회 실패 → 에러 배너 + "셀렉형으로 직접 조립" 유도.
- 실행 실패(권한·문법·캡초과) → 원인 메시지 + SQL 펼쳐 노출.

## 7. 슬라이스
- **[독립] S1** GAS 프록시 스캐폴드 + Gemini 호출(NL+지침+트림카탈로그 → {sql, explanation}) + 키 Script Properties.
- **[의존:S1] S2** 출력가드 + 자가수정 1회.
- **[의존:S2] S3** BQ dry-run(비용추정) + 실행(maximumBytesBilled 캡) → rows.
- **[의존:S3] S4** 클라이언트 대화형: 질문→프록시→결과 표 + 자동 차트 + 접힌 SQL(디자인 게이트).
- **[의존:S4] S5** 후속 질문(맥락 유지) + 셀렉형 실행 승격.
- **[의존:S3] S6** ad_banner CTR 문장 라이브검증.

## 8. 배포/HITL
- clasp로 배포 시도(intakehub에서 clasp v3 경험). 실패 시 사용자 스크립트에디터 수동.
- 사용자 필요 작업: ①웹앱 소유자권한 배포 승인 ②BigQuery 고급서비스 활성화·스코프 동의 ③`GEMINI_API_KEY` Script Property 주입.

## 9. 리스크
- BQ 실행 = 실제 스캔비용(→ dry-run+캡으로 통제).
- 소유자 권한 노출(웹앱 접근자가 소유자 BQ 권한으로 실행) → 기존 비밀번호 게이트(ACCESS_KEY) 유지, 필요 시 강화.
- Gemini SQL 정확도 → grounding+가드+자가수정으로 방어, 최종은 라이브검증(S6).
