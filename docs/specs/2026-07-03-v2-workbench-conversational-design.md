# v2: 워크벤치 스플릿 + 대화형 입력 — 설계 스펙

작성일: 2026-07-03 · 전제: v1(S1~S7) 라이브. 디자인 게이트 통과: 레이아웃 A안(워크벤치 스플릿, `docs/design/layout-options-v2.png` 상단).

## 1. 레이아웃 개편 (A안)

- **헤더**: 로고 + 프로퍼티 탭(고방/U사장님) + 우측 모드 세그먼트(대화형 | 셀렉형)
- **좌측 패널(46%)**: 입력 영역. 모드에 따라 대화형(문장 입력+해석 칩) 또는 셀렉형(기존 기간·이벤트·차원/지표·필터 + 신규 "사람 조건" 섹션) 표시
- **우측 패널(54%, sticky)**: **구조 미리보기 표(상단) + SQL(하단)이 항상 표시.** 좌측에서 무엇을 바꾸든 미리보기 즉시 갱신. SQL은 생성 후 표시, 선택 변경 시 stale 처리(기존 동작 유지)
- 반응형: 1024px 미만은 상하 스택(입력 위, 미리보기 아래)
- 집계/상세(Wide) 토글은 셀렉형 안에 유지. **대화형은 집계 전용** — 로우데이터 요청 감지 시 "상세 모드는 셀렉형에서" 안내
- 게이트·디자인 토큰(A안 콘솔 라이트)·비용가드는 전부 기존 유지

## 2. 세그먼트 엔진 확장 (사람 조건)

"~한 사람 중 ~안 한 사람들이 발생시킨 X" 지원. 지침의 파생 CTE 패턴 준수.

- 선택상태 확장: `segments: { event: string; did: boolean }[]` (0..n개)
- SQL 구조:
  ```
  WITH base AS (원본 스캔 — 대상 이벤트 + 세그먼트 이벤트 전부 IN, 기간 동일),
  seg_users AS (
    SELECT user_pseudo_id FROM base
    GROUP BY user_pseudo_id
    HAVING COUNTIF(event_name = 'A') > 0      -- did=true
       AND COUNTIF(event_name = 'B') = 0      -- did=false
  ),
  target AS (SELECT * FROM base WHERE event_name IN (대상) AND user_pseudo_id IN (SELECT user_pseudo_id FROM seg_users))
  SELECT ... 집계
  ```
- 세그먼트 판정 기간 = 조회 기간과 동일(기본). 주석 Assumptions에 명시
- 셀렉형에도 "사람 조건" 섹션 추가(이벤트 선택 + 했다/안 했다 토글) — 대화형·셀렉형이 같은 상태를 공유
- 스냅샷 테스트 필수 (did만/notDid만/혼합/세그먼트 0개 회귀)

## 3. 대화형 파서 (LLM 0 — 규칙 기반)

**정직한 범위**: 자유 문장 전부가 아니라 "기간 + 사람조건(0..n) + 대상/지표 (+차원)" 문형 + 카탈로그 사전. 해석 결과를 칩으로 보여주고 확인받는 게 UX의 핵심.

- **기간 사전**: 지난 한 주/일주일/최근 7일→7일, 지난 달/한 달/30일→30일, 어제/오늘, "N일" 패턴, "M월 D일~M월 D일"
- **세그먼트 문형**: "X(를/을) 한|누른|본|남긴|제출한 사람( 중)?" → did(X) / "X(를)? (하지 않은|안 한|안 누른)" → notDid(X)
- **대상/지표**: "조회수/문의수/가입수/~수" → 이벤트 후보 + 지표(이벤트수), "사용자 수/명" → 고유사용자수, "몇 번/횟수" → 이벤트수. 이벤트 매칭은 카탈로그 라벨·이벤트명·유의어 사전(`src/nl/dictionary.ts` — 카탈로그에서 생성 + 수동 유의어: 찜 메모→zzim_memo_*, 공고완독→read_complete_notices, 조회수→branch_view·youth_notices·page_view 후보 등)
- **해석 칩**: 확정(파랑) / 되물음(노랑 — 후보 2+ 또는 필수값 누락). 되물음 칩 클릭 → 후보 선택 팝오버. 전부 확정돼야 "이대로 SQL 생성" 활성
- **거절 규칙** (감지 → 이유 + 대안 안내, 생성 차단):
  1. 순서 조건: "하고 나서/이후에/다음에/했다가" → "발생 여부 조건으로 바꿔드릴까요" 제안
  2. 기간 비교: "대비/증감/전주/지난주와" → "두 기간 각각 생성해 비교" 안내
  3. 리텐션/코호트: "잔존/리텐션/N주차" → 미지원 명시
  4. 프로퍼티 교차: "고방이랑 U사장님" 동시 언급 → 하나씩 안내
  5. 인식 실패(대상 이벤트 0매치) → "이해하지 못했어요" + 가능한 문형 예시 + 셀렉형 유도
- 파서는 순수 함수(`src/nl/parse.ts`) + vitest 테스트(예시 문장 포함 15+ 케이스)
