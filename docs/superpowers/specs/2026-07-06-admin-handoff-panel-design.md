# 관리자 핸드오프 패널 — 설계

- 작성일: 2026-07-06
- 상태: 승인됨 (구현 대기)
- 관련: `data/taxonomy-*.json`, `data/inventory-*.json`, `scripts/build-catalog.mjs`, `src/config.ts`, `src/ui/gate.ts`

## 1. 배경 / 문제

BQ 쿼리 빌더는 노션 GTM 택소노미를 **실시간으로 보지 않는다.** 노션에서 수동 추출한 스냅샷(`data/taxonomy-*.json`) + BQ 실측 인벤토리(`data/inventory-*.json`)를 **빌드 시점**에 병합해 `src/data/catalog.json`을 만든다. GTM 이벤트가 추가되거나 택소노미가 바뀌면 사람이 수동으로 갱신해야 한다.

현재 갱신 절차(README "카탈로그 갱신")는 문서로만 존재해 매번 손이 많이 간다. 관리자(소유자 1인)가 이 갱신을 **손쉽게 트리거**할 수 있는 도구가 필요하다.

## 2. 목표 / 비목표

### 목표
- 관리자 전용(비번) 진입점 하나 추가.
- 관리자가 **Claude 세션에 넘겨야 하는 데이터를 손쉽게 패키징·전달**하도록 돕는다.
- 갱신 결과는 기존 배포 파이프라인(빌드→GitHub Actions)을 거쳐 UX팀에 반영된다.

### 비목표 (YAGNI — 명시적으로 안 함)
- 브라우저에서 노션 API 직접 호출 ✗ (CORS·시크릿 불가)
- 브라우저에서 BQ 직접 실행 ✗ (도구 철학: 실행은 사람이 콘솔에서)
- 브라우저에서 diff 계산·JSON 생성 ✗ (Claude가 담당)
- 실시간 팀 반영 ✗ (배포 사이클 경유)
- 백엔드(GAS/DB) 저장·오버레이 ✗

## 3. 결정된 아키텍처

**Claude 연동 동기화 + 배포 경유.** 실제 동기화(노션 읽기·병합·JSON 갱신·빌드·커밋·푸시)는 **Claude 세션이 수행**한다(Claude는 노션 MCP로 택소노미 DB를 직접 읽을 수 있음 — 사전검증 통과). 브라우저 패널은 그 세션에 넘길 데이터를 모아 **핸드오프 텍스트로 패키징**하는 역할만 한다.

```
[관리자 패널 (#admin, 비번)]
  프로퍼티 선택 → 노션URL 확인 → 검증쿼리 복사
    → (관리자가 BQ 콘솔서 실행) → 결과 붙여넣기
    → [Claude 핸드오프 텍스트 복사]
        │
        ▼  (관리자가 Claude 세션에 붙여넣기)
[Claude 세션]
  노션 MCP로 택소노미 DB 읽기(보관 제외) + 붙여넣은 BQ 실측 병합
    → data/taxonomy-*.json / data/inventory-*.json 갱신
    → npm run build:catalog → diff 요약 → commit·push
        │
        ▼
[GitHub Actions] 자동 빌드·배포 → UX팀 반영
```

## 4. 사전검증 결과 (2026-07-06)

Claude가 노션 택소노미 DB 접근 가능함을 확인:

- 고방 페이지·DB fetch ✅ (스키마·뷰 읽힘)
- 고방 이벤트 DB 컬럼 ✅ 택소노미 JSON과 대응 (아래 매핑)
- 뷰 필터 `전체`(상태≠보관) ✅ → 라이브 이벤트만 추출 가능
- 행(row) SQL 조회 ⏳ 조회 라우터 일시 throttle(429, 처리량 제한 — 권한 문제 아님). → **동기화 시 backoff/재시도 필요**.

### 구조 차이 (중요)
- **고방**: 페이지 안에 이벤트 DB가 직접 존재.
  - 페이지 `39138269954380d1a050e73b48616eed`
  - 이벤트 DB `collection://a9338269-9543-83c1-b362-07ccd99331b4`
- **U사장님**: 페이지엔 "텍소노미 버전" 목록 DB만 있고, 실제 이벤트는 **버전 페이지에 중첩**.
  - 페이지 `3913826995438057b59ed6bbbfdb2266`
  - 버전 DB `collection://8d138269-9543-8330-abf8-07eeb32d0f10`
  - 실제 이벤트 DB 위치는 **구현 시 최신 버전 페이지를 타고 들어가 확정**한다.

두 프로퍼티의 노션 구조가 다르므로 Claude 동기화 로직은 프로퍼티별로 분기한다.

## 6. 패널 상세

### 6.1 진입·인증
- URL 해시 `#admin` 진입.
- 관리자 비번 상수 `ADMIN_KEY` (`src/config.ts`). 팀 게이트 `ACCESS_KEY`와 별개.
- 정적 사이트 한계상 클라이언트 검증(기존 게이트 수준). 패널은 텍스트 패키징만 하고 파괴적 백엔드가 없어 이 수준으로 충분. 팀원에게 노출/안내하지 않음.
- 인증 상태는 세션 동안만(별도 localStorage 키, 예: `bqb_admin`).

### 6.2 구성 (3단계)
1. **프로퍼티 선택**: 고방 / U사장님. 선택 시 그 프로퍼티의 **등록된 노션 택소노미 URL** 표시(상수).
2. **BQ 검증쿼리 생성**: 기간(시작~끝) 입력 → 데이터셋·기간 채운 검증쿼리(`docs/verify-query.sql` 기반) 생성 → **[복사]**.
3. **결과 붙여넣기 + 핸드오프**: BQ 실측 결과(JSON/NDJSON/표) 붙여넣기 textarea → **[Claude 핸드오프 텍스트 복사]**.

### 6.3 핸드오프 패키지 포맷
`[Claude 핸드오프 텍스트 복사]`가 클립보드에 넣는 내용:

```
카탈로그 동기화 요청.
- property: 고방 (analytics_274122040)
- 노션 택소노미: <등록 URL>
- 기간: <시작> ~ <끝>
- 아래는 BQ 실측 인벤토리 결과:
<붙여넣은 결과 원문>

지시: 노션 택소노미(위 URL, 보관 제외)를 읽어 data/taxonomy-<prop>.json 갱신 +
이 실측으로 data/inventory-<prop>.json 갱신 → npm run build:catalog →
diff 요약을 보여주고 커밋·push 해줘.
```

붙여넣은 결과가 비어 있으면 [복사] 비활성 + 안내.

### 6.4 상수 (config.ts 등)
- `ADMIN_KEY`
- 프로퍼티별 노션 URL:
  - 고방: `https://app.notion.com/p/GTM-1-39138269954380d1a050e73b48616eed`
  - U사장님: `https://app.notion.com/p/U-GTM-1-3913826995438057b59ed6bbbfdb2266`

## 9. 리스크 / 오픈 이슈

- **노션 조회 throttle(429)**: 동기화 시 backoff·재시도 또는 fetch(뷰) 방식 병행. (패널이 아니라 Claude 동기화 절차의 문제.)
- **U사장님 실제 택소노미 위치**: 버전 DB 중첩 구조 — 구현 시 최신 버전 페이지 확정 필요.
- **클라이언트 비번의 약함**: 외부인 차단용 수준. 소유자 단독 사용·비파괴 도구라 수용.
